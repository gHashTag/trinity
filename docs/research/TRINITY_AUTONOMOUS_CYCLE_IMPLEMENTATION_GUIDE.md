## Overview

The Trinity autonomous cycle is a 10-minute continuous improvement loop that:
1. Fixes build errors and test failures without user intervention
2. Commits each completion with meaningful messages
3. Formats code with `zig fmt`
4. Studies codebase and scientific papers deeply
5. Proposes improvements based on best patterns
6. Reports progress at milestones

**Rule No Questions**: The agent acts autonomously - no confirmations requested.

### 2. Dev Session Management

```bash
# Check current session
cat .trinity/dev_session.json

# Update state
# ACTIVE: Working on task
# TESTED: Tests passed, ready to commit
# COMMITTED: Changes committed

# Mark as completed when done
echo '{"state": "TESTED", "issue_number": <CURRENT_ISSUE>}' > .trinity/dev_session.json

# Commit
git add <files> && git commit -m "feat(scope): description (#<ISSUE>)"

# Reset for next task
echo '{"state": "ACTIVE", "issue_number": <NEXT_ISSUE>}' > .trinity/dev_session.json
```

### 5. FAIR Principles Checklist

- [ ] Title ≤ 100 chars, descriptive
- [ ] Authors with full name, affiliation
- [ ] Description 500-1000 words
- [ ] 5-10 relevant keywords
- [ ] License CC-BY-4.0
- [ ] DOI (auto-generated by Zenodo)
- [ ] References formatted consistently
- [ ] Reproducibility instructions tested
- [ ] All methods described in detail
- [ ] All results with error bars/confidence intervals
- [ ] CITATION.cff included
- [ ] LICENSE file included
- [ ] Keywords ≤ 10

## 9. Development Workflow

### Before Starting Cycle

1. Check `git status` for uncommitted changes
2. Read `CLAUDE.md` for project rules
3. Identify priority areas (build errors, test failures, documentation)
4. Set timer for 10 minutes

### During Cycle

1. **Minute 1-2**: Quick assessment and prioritization
   - Run `zig build` - check for errors
   - Run `zig build test` - verify tests
   - Identify low-effort fixes (10-30 seconds)
   - Commit each fix immediately

2. **Minute 3-6**: Code improvements
   - Fix identified issues
   - Add missing documentation
   - Format code: `zig fmt`
   - Commit: `fix(scope): description (#<ISSUE>)`

3. **Minute 7-9**: Scientific work
   - Study existing papers
   - Create new documentation
   - Update Zenodo templates
   - Propose improvements

4. **Minute 10**: Final review and commit
   - Run final test suite
   - Commit major improvements
   - Update memory files

### After Cycle

1. Create GitHub issue for cycle work
2. Commit all changes to issue
3. Push to remote (optional)

## 2. Scientific Writing Guidelines

### 2.1 Abstract Structure

Abstracts MUST follow this 5-sentence structure:

1. **Problem** (1 sentence): What problem does this solve?
2. **Gap** (1 sentence): What's missing in current solutions?
3. **Solution** (1 sentence): What is our novel approach?
4. **Results** (1-2 sentences): What quantitative results did we achieve?
5. **Impact** (1 sentence): What are the applications/benefits?

**Example:**
```
Language models require massive memory and compute resources (problem).
Existing ternary approaches still require DSP blocks, limiting deployment (gap).
We present HSLM, a zero-DSP ternary LLM using pure LUT-based inference (solution).
Our 1.95M parameter model achieves PPL 125 on TinyStories with 385 KB model size (results).
This enables edge AI deployment on resource-constrained FPGAs (impact).
```

### 2.2 Novelty Statement Format

Novelty claims MUST be specific and verifiable:

**Good Example:**
```
1. **Claim 1**: Ternary MAC unit using 3 LUTs per weight, achieving 0% DSP utilization
   on Xilinx XC7A100T FPGA (verified by synthesis report).

2. **Claim 2**: Checkpoint compression algorithm achieving 20× size reduction
   from 7.6 MB (FP32) to 385 KB (TF3) with <1% accuracy loss.
```

**Bad Example:**
```
1. **Claim 1**: Better performance than existing methods.
2. **Claim 2**: Novel approach for model compression.
```

### 2.3 Claims Formatting Rules

- Use `**Claim N:**` format (colon, NOT closing brace)
- Each claim MUST be verifiable by experiment/code
- Include quantitative metrics where applicable
- Reference specific files/figures when possible

**Correct Format:**
```markdown
1. **Claim 1**: Description of claim with quantitative result
2. **Claim 2**: Another claim with specific metrics
```

**Incorrect Format:**
```markdown
1. **Claim 1}: Description (wrong: uses closing brace)
2. **Claim 2}: Another claim (wrong: uses closing brace)
```

### 2.4 Mathematical Notation

- Use LaTeX notation for equations: `$\phi^2 + 1/\phi^2 = 3$`
- Define all variables before first use
- Include units in all measurements
- Use significant figures appropriate to precision

**Example:**
```
Let $\phi = (1 + \sqrt{5}) / 2 \approx 1.618$ be the golden ratio.
The Trinity Identity states: $\phi^2 + 1/\phi^2 = 3$.
```

## 3. Statistical Analysis Requirements

### 3.1 Confidence Intervals

All reported metrics MUST include 95% confidence intervals:

**Format:**
```
Metric: 125.3 ± 2.1 (95% CI: [123.2, 127.4])
```

**Python Code for CI Calculation:**
```python
import numpy as np
from scipy import stats

def compute_ci(values: np.ndarray, confidence: float = 0.95) -> tuple:
    """Compute confidence interval for mean."""
    n = len(values)
    mean = np.mean(values)
    std = np.std(values, ddof=1)
    se = std / np.sqrt(n)
    t_val = stats.t.ppf((1 + confidence) / 2, n - 1)
    margin = t_val * se
    return mean, mean - margin, mean + margin
```

### 3.2 Statistical Significance

When comparing against baselines:
- Report p-values for statistical tests
- Use appropriate test (t-test, Wilcoxon, etc.)
- State sample size (n)
- Report effect size (Cohen's d)

**Format:**
```
Our method (PPL: 125.3 ± 2.1, n=5) significantly outperforms
baseline (PPL: 135.7 ± 3.4, n=5): t(8) = 5.23, p < 0.001,
Cohen's d = 2.34 (large effect).
```

### 3.3 Bootstrap Validation

For non-parametric validation:

```python
def bootstrap_ci(values: np.ndarray, n_bootstrap: int = 10000) -> tuple:
    """Compute bootstrap confidence interval."""
    boot_means = []
    for _ in range(n_bootstrap):
        sample = np.random.choice(values, size=len(values), replace=True)
        boot_means.append(np.mean(sample))
    return np.percentile(boot_means, [2.5, 97.5])
```

## 6. Code Examples

### 6.1 Code Quality Standards

All code examples MUST:
- Compile without errors
- Follow language style guidelines (zig fmt)
- Include comments explaining key algorithms
- Handle errors appropriately
- Include test cases

### 6.2 Zig Code Template

```zig
const std = @import("std");

/// Ternary weight representation
pub const Trit = enum(i2) { neg = -1, zero = 0, pos = 1 };

/// Ternary multiply-accumulate
pub fn mac(
    weights: []const Trit,
    inputs: []const f16,
    output: []f16,
) !void {
    std.debug.assert(weights.len == inputs.len);
    std.debug.assert(inputs.len == output.len);

    for (weights, inputs, 0..) |w, x, i| {
        const contribution = switch (w) {
            .pos => x,
            .neg => -x,
            .zero => 0,
        };
        output[i] += contribution;
    }
}

test "ternary MAC correctness" {
    const weights = [_]Trit{ .pos, .neg, .zero };
    const inputs = [_]f16{ 1.0, 2.0, 3.0 };
    var output = [_]f16{0.0} ** 3;

    try mac(&weights, &inputs, &output);

    try std.testing.expectEqual(@as(f16, 1.0), output[0]);
    try std.testing.expectEqual(@as(f16, -2.0), output[1]);
    try std.testing.expectEqual(@as(f16, 0.0), output[2]);
}
```

## 7. Quality Checklist

### 7.1 Pre-Publication Checklist

Each discovery MUST pass all checks before publication:

**Content Quality:**
- [ ] Abstract ≤ 250 words, follows 5-sentence structure
- [ ] Novelty statement includes 3-5 specific, verifiable claims
- [ ] All claims use correct formatting (`**Claim N:**` not `**Claim N}:`)
- [ ] Problem statement clearly identifies gaps in prior art
- [ ] Related work table includes at least 3 baselines

**Scientific Rigor:**
- [ ] All metrics include confidence intervals or error bars
- [ ] Statistical significance tests reported where applicable
- [ ] Sample sizes (n) reported for all experiments
- [ ] Random seeds specified for reproducibility
- [ ] Hardware/software environment fully documented

**Code and Data:**
- [ ] Code compiles and tests pass
- [ ] Build instructions tested on fresh environment
- [ ] Docker image builds successfully
- [ ] Data sources cited with URLs

**Formatting:**
- [ ] All figures have descriptive captions
- [ ] All tables have headers with units
- [ ] Mathematical notation uses LaTeX
- [ ] Citations follow consistent format (BibTeX recommended)

**Accessibility:**
- [ ] Alt text provided for all figures
- [ ] Tables use Markdown format (screen reader friendly)
- [ ] Code examples use syntax highlighting
- [ ] Color not the only means of conveying information

### 7.2 Automated Quality Check

```bash
#!/bin/bash
# quality_check.sh — Automated quality checker

echo "=== Trinity Discovery Quality Check ==="

# Check for claim formatting errors
echo "Checking claim formatting..."
if grep -r "Claim.*}:" docs/research/discovery/*.md; then
    echo "❌ Found claim formatting errors (using } instead of :)"
    exit 1
else
    echo "✅ Claim formatting correct"
fi

# Check for TBD DOIs
echo "Checking DOI status..."
if grep -r "doi:.*TBD" docs/research/discovery/*.md; then
    echo "⚠️  Some DOIs still marked as TBD"
else
    echo "✅ All DOIs assigned"
fi

# Check for abstract length
echo "Checking abstract lengths..."
for file in docs/research/discovery/p*.md; do
    abstract=$(sed -n '/## 1. Abstract/,/^---$/p' "$file" | wc -w)
    if [ $abstract -gt 300 ]; then
        echo "⚠️  $file: Abstract too long ($abstract words)"
    fi
done

# Check for test coverage
echo "Checking code tests..."
zig build test 2>&1 | grep -q "All tests passed"
if [ $? -eq 0 ]; then
    echo "✅ All tests passing"
else
    echo "❌ Some tests failing"
    exit 1
fi

echo "=== Quality check complete ==="
```

## 8. Publication Workflow

### 8.1 Pre-Publication Steps

1. **Content Review**
   - Verify all claims are verifiable
   - Check statistical analysis is correct
   - Ensure reproducibility instructions work

2. **Peer Review**
   - Internal review by team member
   - External review if possible
   - Address all feedback

3. **Final Polish**
   - Run automated quality check
   - Verify all formatting is consistent
   - Check accessibility compliance

### 8.2 Zenodo Upload Process

```bash
# 1. Create release bundle
mkdir bundle_v1.0.0
cd bundle_v1.0.0

# 2. Add files
cp ../README.md .
cp ../CITATION.cff .
cp ../LICENSE .
cp -r ../discovery/*.md .
cp -r ../code .
cp -r ../docs .

# 3. Create checksums
sha256sum * > CHECKSUMS.sha256

# 4. Create tarball
cd ..
tar czf trinity_bundle_v1.0.0.tar.gz bundle_v1.0.0/

# 5. Upload via Zenodo web UI or API
# Use Zenodo REST API for automated upload
```

### 8.3 Post-Publication

1. **Record DOI** in all related files
2. **Update** PRIOR_ART_NETWORK.md with new DOI
3. **Announce** on relevant channels
4. **Monitor** for citations and downloads
5. **Archive** publication materials
